# Phase 06 Jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. Steps follow TDD internally, but this project is executing continuously without user approval gates between tasks.

**Goal:** Turn a fake-paid proposal into a schedulable, auditable Job that can proceed through execution, rescheduling, scope changes, completion, cancellation, dispute and no-show states without double booking or leaking private location data.

**Architecture:** PostgreSQL remains the source of truth. Job state changes, schedule acceptance, conflict prevention and scope-price changes are performed only through transactional SECURITY DEFINER RPCs with fixed `search_path`; authenticated clients keep read-only table access under RLS. The web layer calls typed server helpers/actions and renders a mobile-first job timeline.

**Tech Stack:** Next.js App Router, TypeScript, Supabase PostgreSQL/Auth/RLS, pgTAP, PostGIS, Vitest, Playwright.

**Spec:** `CHANGAS_MASTER_PLAN.md` — Phase 06.

## Global Constraints

- Money remains integer minor units; never floating point.
- No real payment provider in Phase 06.
- Accepted proposal snapshots remain immutable.
- Job state transitions are server-enforced and auditable.
- Realtime/chat history is not economic truth.
- Exact private address is participant-only and never public.
- No direct authenticated INSERT/UPDATE/DELETE on economic tables.
